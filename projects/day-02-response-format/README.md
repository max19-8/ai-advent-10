# День 02. Формат ответа

Введите любой вопрос — скрипт отправит его в четырёх режимах по одному разу,
а затем проверит, можно ли прочитать каждый ответ кодом. Всего до **4 запроса**.

**Стек:** Python 3.9+, requests, python-dotenv, jsonschema, Cloudflare Workers AI.
**Модель:** `@cf/meta/llama-3.3-70b-instruct-fp8-fast`.
Используется OpenAI-совместимый endpoint `/ai/v1/chat/completions`, без SDK.

## Как работает эксперимент

| Вариант | Что отправляется |
| --- | --- |
| 1. Строгая схема | Только исходный вопрос в `messages`; JSON Schema через `response_format`; без явного `max_tokens` и без `stop` |
| 2. Без ограничений | Только вопрос, без требований к формату, явного `max_tokens` и `stop` |
| 3. Лимит 50 токенов | Только вопрос + `max_tokens=50`; формат свободный |
| 4. Описание формата | Вопрос + просьба вернуть JSON с полем `answer`, затем маркер `<END>`; `stop=["<END>"]`; без явного `max_tokens` |

Каждый вариант выполняется один раз. Stop sequence добавлена в четвёртый вариант,
чтобы сохранить четыре конфигурации и покрыть все пункты задания.
Во всех вариантах без явного `max_tokens` действует лимит Cloudflare по умолчанию.

Для каждого полученного ответа `json.loads` проверяет возможность разбора полного
текста без исправлений, затем `jsonschema` проверяет структуру. Результаты
сохраняются в `.json`, без добавления комментариев скрипта в Markdown-отчёт.

## Задание, которое покрывает скрипт

Отправить один и тот же запрос с явным описанием формата, ограничением объёма
через `max_tokens`, stop sequence и строгой JSON Schema / structured output;
по исходному заданию каждый вариант нужно повторить несколько раз.
В текущей версии по решению пользователя выполняется один запрос на вариант;
повторы возможны отдельным запуском программы.
Сравнить ответы без ограничений, с ограничениями и со строгой схемой;
проверить разбор ответов кодом и сделать вывод, какой способ ломается и на чём.
Сравнение и выводы делаем по сохранённым ответам и результатам проверок,
а не генерируем заранее.

Универсальная схема для любого вопроса:

```json
{
  "type": "object",
  "properties": {"answer": {"type": "string"}},
  "required": ["answer"],
  "additionalProperties": false
}
```

В поле `answer` может быть объяснение, список идей, код или другой текст.
Схема управляет формой ответа, но не проверяет правильность его содержания.

Токены — части текста, а не слова. При лимите 50 токенов длинный ответ может
оборваться посреди слова. Даже в режимах без нашего лимита ответ может обрезать Cloudflare. Изменять вопрос между отдельными
обращениями внутри одного прогона скрипт не будет.

Общие настройки: одна модель, `temperature=0.6`, без потоковой выдачи и истории диалога.
Порядок: схема → без ограничений → лимит 50 → описание формата.
Первый запрос проверяет поддержку схемы и входит в четыре обращения.
При отклонении запроса со схемой или сетевой ошибке прогон останавливается;
частичный результат сохраняется. Автоматических повторных попыток нет.

## Установка и запуск

Из корня репозитория:

```bash
cd projects/day-02-response-format
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp -n .env.example .env
```

Заполните токен и Account ID в `.env`. Файл читается рядом с `main.py`;
переменные окружения имеют приоритет. Если экспортирована устаревшая модель
первого дня, выполните `unset CLOUDFLARE_MODEL` или задайте актуальную модель.
`.env` и `.venv` исключены из Git.

```bash
python main.py
```

Например, на приглашение `Введите вопрос:` можно ответить:

```text
Чем список отличается от кортежа в Python?
```

Для другого вопроса просто запустите программу снова — код менять не нужно.
Cloudflare учитывает запросы в квоте аккаунта.

## Где смотреть результаты

В `results/` сохраняются два файла с временем запуска в имени:

- `.md` — для каждого из четырёх ответов только «запрос → условия → вывод LLM», без анализа и выводов скрипта.
- `.json` — исходный вопрос, схема, параметры запросов, ответы API и результаты автоматических проверок;
  заголовки авторизации не сохраняются.

Файлы разных прогонов не перезаписываются. Ошибки API учитываются отдельно от
невалидного JSON модели. Если JSON не читается, проверка схемы не запускается.
`finish_reason=length` означает остановку по лимиту длины;
`stop_reason=<END>` подтверждает срабатывание маркера.

Код завершения 1 означает ошибку API или неполный прогон; невалидный JSON сам
по себе не меняет код завершения, поскольку это результат эксперимента.
Один ответ на режим не показывает стабильность; отдельный вклад объединённых ограничений
не измеряется. Содержательную правильность ответа оцениваем вручную.

## Выводы по сохранённому прогону

Один запрос: **«Предложи три учебных проекта на Python для начинающего.
Для каждого укажи название и одним коротким предложением объясни, чему он научит»**.
Все четыре обращения к Cloudflare выполнены успешно.

| Вариант | Токенов ответа | JSON читается кодом | Наблюдение |
| --- | ---: | --- | --- |
| Строгая схема | 120 | Да; схема соблюдена | В строке `answer` перечислены все три проекта с объяснениями |
| Без ограничений | 96 | Нет | Получен законченный текстовый список трёх проектов; JSON в этом режиме не требовался |
| Лимит 50 токенов | 50 | Нет | Первый проект описан полностью, второй оборван на «Позволит познакомиться с работой», третий отсутствует; `finish_reason=length` |
| Описание формата + stop sequence | 66 | Да; схема соблюдена | В строке `answer` перечислены три проекта; `stop_reason=<END>` подтверждает остановку на маркере |

**Что сломалось:** в варианте с 50 токенами не выполнено содержательное требование
дать три проекта с объяснениями. API прекратил генерацию при достижении лимита,
не дожидаясь законченного предложения или полного списка.
Следовательно, `max_tokens` ограничивает длину генерации, но не заставляет
модель уместить все запрошенные сведения в этот бюджет.

**Что сработало:** текстовая инструкция со stop sequence и строгая схема дали
целый JSON, который разобрался через `json.loads` и прошёл `jsonschema`.
Свободный ответ тоже выполнил задачу по содержанию, но не подходит для прямого
разбора как JSON — это ожидаемое поведение при отсутствии требования к формату,
а не ошибка модели. Парсер отклоняет нумерованный текстовый список.

На этом прогоне нельзя установить превосходство строгой схемы над текстовым
описанием формата: оба режима сработали. Влияние stop sequence отдельно не
измерялось, но её срабатывание подтверждено API. Универсальная схема проверяет
только поле `answer` и его тип; наличие трёх проектов в тексте проверено вручную.
По одному ответу на вариант нельзя судить о стабильности. Для пункта курса
«несколько раз» потребуется повторить запуск с тем же вопросом.
